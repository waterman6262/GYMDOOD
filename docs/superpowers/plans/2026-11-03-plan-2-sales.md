# Gym POS — Plan 2: ขาย + ใบเสร็จ + ยกเลิกบิล Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** พนักงานขายแพ็กเกจสมาชิกได้จริง: เลือกสมาชิก → ใส่แพ็กเกจลงตะกร้า → ส่วนลด → ชำระเงิน (เงินสด/โอน/QR PromptPay) → ได้ใบเสร็จที่พิมพ์หรือแชร์ลิงก์ได้ และเจ้าของยกเลิกบิลได้ (ขั้นที่ 2 ของสเปกข้อ 10)

**Architecture:** การเขียนข้อมูลการขายทั้งหมดผ่านฟังก์ชัน PostgreSQL (`create_sale`, `void_sale`) ที่ทำงานใน transaction เดียว ตาราง `sales`, `sale_items`, `memberships` ไม่มี policy insert/update ให้ client เลย หน้าจอคำนวณยอดไว้แสดงผล แต่ฐานข้อมูลคำนวณใหม่เองจากราคาในตารางเสมอ ใบเสร็จสาธารณะอ่านผ่านฟังก์ชัน `get_receipt(token)` ที่คืนเฉพาะข้อมูลที่อนุญาต

**Tech Stack:** ต่อจากแผน 1 + `promptpay-qr` (สร้าง payload PromptPay, MIT) + `qrcode` (วาด QR เป็น SVG, MIT)

**Spec:** `docs/superpowers/specs/2026-11-03-gym-pos-design.md` (ข้อ 5.2, 5.3, 5.6, 6.2, 6.3)

## Global Constraints

- ทุกวันที่ของแพ็กเกจคิดตามวันในเขตเวลา `Asia/Bangkok` ไม่ใช่ UTC
- เลขใบเสร็จรูปแบบ `R{ปี ค.ศ.}-{ลำดับ 6 หลัก}` เช่น `R2026-000123` รันต่อเนื่องแยกตามปี และไม่ซ้ำ
- เงินเป็น `numeric(10,2)` ยอดสุทธิต้องไม่ติดลบ
- Client เขียน `sales`, `sale_items`, `memberships` ตรง ๆ ไม่ได้ ต้องผ่าน `create_sale` / `void_sale` เท่านั้น
- ราคาที่บันทึกมาจาก `package_types.price` ในฐานข้อมูล ไม่เชื่อราคาที่ client ส่งมา
- ยกเลิกบิลได้เฉพาะเจ้าของ ต้องใส่เหตุผล และบิลไม่ถูกลบ
- หน้าใบเสร็จสาธารณะ `/r/{token}` แสดงชื่อสมาชิกได้ แต่ห้ามแสดงเบอร์โทร, LINE หรือหมายเหตุ
- ข้อความบนหน้าจอและข้อความผิดพลาดเป็นภาษาไทย

## ขอบเขต

- **ในแผนนี้:** ขายแพ็กเกจ (ทุกชนิด รวมแพ็กเกจคู่), ส่วนลด, วิธีชำระ 3 แบบ, เลขใบเสร็จ, กันบิลซ้ำ, ใบเสร็จบนจอ/พิมพ์/ลิงก์, ยกเลิกบิล, รายการบิล, แพ็กเกจของสมาชิกในหน้ารายละเอียดสมาชิก

## Review Focus

1. แท็บเล็ต 2 เครื่องขายพร้อมกัน → เลขใบเสร็จต้องไม่ซ้ำและไม่ข้าม (Task 1: `receipt_numbers_consecutive` + ล็อกแถว counter)

# Gym POS — Design Spec (เวอร์ชัน 1)

- วันที่: 2026-11-03
- สถานะ: รอเจ้าของตรวจ

## 1. เป้าหมาย

ระบบ POS สำหรับยิม 1 สาขา (สมาชิกประมาณ 100–200 คน) ใช้เองภายในยิม ทำงานเป็นเว็บแอป (PWA) ที่ติดตั้งบนแท็บเล็ตหน้าเคาน์เตอร์ และเจ้าของเปิดดูจากมือถือได้

**ถือว่าสำเร็จเมื่อ**
- พนักงานขายแพ็กเกจหรือสินค้าจบได้ในไม่กี่วินาที
- สมาชิกเช็กอินได้ภายใน 3 วินาที
- ระบบบอกได้ทันทีว่าใครหมดอายุ ใกล้หมด หรือพักสมาชิกอยู่
- เจ้าของเห็นยอดขายรายวัน/รายเดือนได้จากที่ไหนก็ได้

### สิ่งที่เจ้าของกำหนดมา
- แพ็กเกจ: รายวัน, ตามระยะเวลา, นับครั้ง, PT, พักสมาชิก (freeze), แพ็กเกจพิเศษ (นักเรียน/คู่)
- คลาส: เวอร์ชัน 1 ให้พนักงานจองให้ที่เคาน์เตอร์ มีจำกัดที่นั่ง และนับคนเข้าได้
- เช็กอิน: สแกน QR เป็นหลัก ค้นชื่อ/เบอร์เป็นทางสำรอง
- สินค้า: ตัดสต็อกอัตโนมัติ รับของเข้า และเตือนเมื่อของใกล้หมด
- ผู้ใช้: เจ้าของ 1 บัญชี และพนักงานเคาน์เตอร์ 1–3 คน
- Deploy: โค้ดอยู่บน GitHub และ deploy ขึ้น Vercel

### สิ่งที่ผู้ออกแบบสมมติเอง (เจ้าของแก้ได้)
- อินเทอร์เน็ตที่ยิมเสถียร จึงไม่ทำโหมดออฟไลน์
- ชำระเงินด้วยเงินสด โอน หรือ QR PromptPay โดยพนักงานกดยืนยันเองว่าได้รับเงินแล้ว ไม่เชื่อมระบบธนาคาร
- สมาชิกที่มีแพ็กเกจเข้ายิมยังใช้งานอยู่ เข้าคลาสได้โดยไม่ต้องซื้อแยก
- สมาชิกที่หมดอายุแล้วมาเช็กอิน: ระบบเตือนและเสนอให้ต่ออายุ แต่พนักงานกดปล่อยเข้าได้โดยต้องใส่เหตุผล
- เวลาและวันทั้งหมดอิงเขตเวลา Asia/Bangkok และใช้สกุลเงินบาท

### นอกขอบเขตเวอร์ชัน 1
- สมาชิกจองคลาสเองผ่านมือถือ (วางไว้เวอร์ชัน 2 และออกแบบข้อมูลรองรับไว้แล้ว)
- บัญชีล็อกอินของเทรนเนอร์ และค่าคอมมิชชัน
- ระบบปิดกะ/นับเงินสด
- ต้นทุนสินค้าและรายงานกำไร
- โหมดออฟไลน์
- หลายสาขา
- ใบกำกับภาษีเต็มรูป

## 2. สถาปัตยกรรม

```
แท็บเล็ตหน้าเคาน์เตอร์ / มือถือเจ้าของ  (PWA)
            │
            ▼
Next.js (App Router, TypeScript) บน Vercel  ← deploy อัตโนมัติเมื่อ push ขึ้น GitHub
            │
            ▼
Supabase: PostgreSQL + Auth + Row Level Security + ฟังก์ชันฐานข้อมูล (RPC)
```

| ส่วน | เลือกใช้ |
|---|---|
| หน้าจอ | Next.js + TypeScript + Tailwind CSS |
| ฐานข้อมูลและล็อกอิน | Supabase (PostgreSQL, ล็อกอินด้วยอีเมล/รหัสผ่าน) |
| สิทธิ์ | Row Level Security บังคับที่ฐานข้อมูล |
| งานที่ต้องสำเร็จพร้อมกัน (ขาย, เช็กอิน, ยกเลิกบิล) | ฟังก์ชัน PostgreSQL เรียกผ่าน RPC แต่ละครั้งเป็น transaction เดียว |
| สแกน QR | กล้องของแท็บเล็ตผ่านเบราว์เซอร์ |
| QR PromptPay | สร้าง payload PromptPay ตามยอดเงินในเครื่อง ไม่ต้องเรียก API ภายนอก |
| ทดสอบ | Vitest (logic), pgTAP หรือ SQL tests (ฟังก์ชันฐานข้อมูล), Playwright (ทดสอบผ่านเบราว์เซอร์) |
| Hosting | Vercel (Hobby) + Supabase (Free) |

**หลักการ:** กติกาธุรกิจที่เกี่ยวกับเงิน สต็อก และสิทธิ์ อยู่ในฟังก์ชันฐานข้อมูล ไม่อยู่ในหน้าจอ เพื่อให้แก้หน้าจอได้โดยไม่ทำให้ข้อมูลผิด

## 3. ผู้ใช้และสิทธิ์

| การกระทำ | เจ้าของ | พนักงาน |
|---|---|---|
| เช็กอิน, ปล่อยเข้าแม้หมดอายุ (ต้องใส่เหตุผล) | ✓ | ✓ |
| ขาย, ใส่ส่วนลด | ✓ | ✓ |
| เพิ่ม/แก้สมาชิก, พักสมาชิก | ✓ | ✓ |
| ปิดการใช้งานสมาชิก | ✓ | – |
| จองคลาส, เช็กชื่อ, นัด PT, ตัดชั่วโมง PT | ✓ | ✓ |
| รับของเข้าสต็อก | ✓ | ✓ |
| ปรับยอดสต็อก, เพิ่ม/แก้สินค้าและราคา | ✓ | – |
| ยกเลิกบิล | ✓ | – |
| รายงานทั้งหมด | ✓ | ยอดขายของวันนี้เท่านั้น |
| ตั้งค่า (แพ็กเกจ, เทรนเนอร์, คลาส, บัญชีพนักงาน, ข้อมูลร้าน) | ✓ | – |

บัญชีพนักงานสร้างได้โดยเจ้าของเท่านั้น ไม่มีหน้าสมัครสมาชิกเอง

## 4. หน้าจอ

1. **เช็กอิน** (หน้าแรกหลังล็อกอิน): สแกน QR หรือค้นชื่อ/เบอร์ แล้วแสดงสถานะ 🟢/🟡/🔴 (ดูข้อ 6.1)
2. **ขาย (POS)**: ตะกร้าเดียวรวมทั้งแพ็กเกจและสินค้า เลือกวิธีชำระ แล้วออกใบเสร็จ
3. **สมาชิก**: รายชื่อ ค้นหา และหน้ารายละเอียด (แพ็กเกจที่ใช้อยู่, ประวัติเข้าใช้, ประวัติซื้อ, พักสมาชิก, บัตร QR)
4. **คลาสและ PT**: ตารางรอบคลาสรายสัปดาห์, จอง, เช็กชื่อ, นัด PT, กด "เทรนแล้ว"
5. **สินค้าและสต็อก**: รายการสินค้า, รับของเข้า, ปรับยอด, รายการของใกล้หมด, ประวัติสต็อก
6. **รายงาน** (ดูข้อ 7)
7. **ตั้งค่า**: แบบแพ็กเกจ, เทรนเนอร์, ชนิดคลาส, บัญชีพนักงาน, ข้อมูลร้าน (ชื่อ, ที่อยู่, เลข PromptPay, ข้อความท้ายใบเสร็จ)

หน้าจอออกแบบสำหรับแท็บเล็ตแนวนอนเป็นหลัก ปุ่มใหญ่พอกดด้วยนิ้ว และใช้บนมือถือได้ (รายงานโดยเฉพาะ)

## 5. โครงสร้างข้อมูล

ทุกตารางมี `id` (uuid), `created_at` และตารางที่มีการกระทำของคนจะเก็บ `created_by` (พนักงาน)

### 5.1 คน
- **staff**: `user_id` (อ้างบัญชี Supabase Auth), `name`, `role` (`owner` | `staff`), `active`
- **members**: `member_code` (สุ่ม ไม่เรียงลำดับ ใช้ทำ QR), `name`, `phone`, `line_id`, `photo_url`, `note`, `active`
- **trainers**: `name`, `phone`, `active`

### 5.2 แพ็กเกจ
- **package_types** (เจ้าของตั้ง):
  - `name`, `price`, `tag` (เช่น "นักเรียน", ไม่บังคับ), `active`
  - `kind`: `day` | `duration` | `visits` | `pt`
  - `duration_days`: จำนวนวันที่ใช้ได้ (`duration`, `visits`, `pt`; `day` = 1)
  - `visits`: จำนวนครั้ง (เฉพาะ `visits`)
  - `pt_sessions`: จำนวนชั่วโมง PT (เฉพาะ `pt`)
  - `seats`: จำนวนสิทธิ์ต่อการขาย 1 ครั้ง (ปกติ 1, แพ็กเกจคู่ = 2)
- **memberships** (แพ็กเกจที่สมาชิกซื้อแล้ว): `member_id`, `package_type_id`, `sale_item_id`, `kind` (สำเนาจากแบบ), `start_date`, `end_date`, `visits_left`, `pt_left`, `status` (`active` | `cancelled`)
  - "หมดอายุ" ไม่ได้เก็บเป็นสถานะ แต่คำนวณจาก `end_date` < วันนี้ หรือครั้ง/ชั่วโมงที่เหลือเป็น 0
  - "พักอยู่" ไม่ได้เก็บเป็นสถานะ แต่คำนวณจากการมีแถวใน freezes ที่ครอบคลุมวันนี้
- **freezes**: `membership_id`, `start_date`, `end_date`, `reason`

### 5.3 การขาย
- **sales**: `receipt_no`, `member_id` (ว่างได้), `subtotal`, `discount`, `total`, `payment_method` (`cash` | `transfer` | `promptpay`), `status` (`paid` | `voided`), `void_reason`, `voided_by`, `voided_at`, `receipt_token` (สุ่ม ใช้ทำลิงก์ใบเสร็จ), `client_request_id` (กันบิลซ้ำ, unique)
- **sale_items**: `sale_id`, `item_type` (`package` | `product`), `package_type_id` หรือ `product_id`, `name` (สำเนาชื่อตอนขาย), `qty`, `unit_price`, `line_total`

### 5.4 สินค้า
- **products**: `name`, `price`, `track_stock`, `stock_qty`, `low_stock_at`, `active`
- **stock_movements**: `product_id`, `change` (+/−), `reason` (`sale` | `receive` | `adjust` | `void`), `sale_id` (ถ้ามี), `note`

### 5.5 การใช้บริการ
- **check_ins**: `member_id`, `membership_id`, `checked_in_at`, `override` (true = ปล่อยเข้าทั้งที่ไม่มีสิทธิ์), `override_reason`, `visit_deducted`
- **class_types**: `name`, `default_capacity`, `active`
- **class_sessions**: `class_type_id`, `trainer_id`, `starts_at`, `ends_at`, `capacity`, `cancelled`
- **class_bookings**: `class_session_id`, `member_id`, `status` (`booked` | `attended` | `no_show` | `cancelled`), unique (`class_session_id`, `member_id`)
- **pt_appointments**: `membership_id` (ชนิด `pt`), `trainer_id`, `starts_at`, `status` (`scheduled` | `done` | `cancelled`)

### 5.6 อื่น ๆ
- **settings** (แถวเดียว): `gym_name`, `address`, `phone`, `promptpay_id`, `receipt_footer`
- **receipt_counters**: เลขใบเสร็จล่าสุดของแต่ละปี

## 6. กติกาและขั้นตอนการทำงาน

### 6.1 เช็กอิน
1. รับ `member_code` จาก QR หรือ `member_id` จากการค้นหา
2. หาแพ็กเกจที่ใช้เข้ายิมได้ คือชนิด `day`, `duration` หรือ `visits`, สถานะ `active`, วันนี้อยู่ระหว่าง `start_date`–`end_date`, ไม่ได้พักอยู่ในวันนี้ และ (ถ้าเป็น `visits`) `visits_left` > 0
3. ถ้ามีหลายแพ็กเกจ เลือกอันที่ `end_date` ใกล้ที่สุด
4. ผลลัพธ์:
   - 🟢 **ใช้ได้**: บันทึก check-in ทันที
   - 🟡 **ใกล้หมด**: เหมือน 🟢 แต่เตือนเพราะเหลือไม่เกิน 7 วัน หรือไม่เกิน 2 ครั้ง และมีปุ่มต่ออายุ
   - 🔴 **ไม่มีสิทธิ์** (หมดอายุ, พักอยู่, ไม่เคยซื้อ): ยังไม่บันทึก แสดงปุ่ม "ต่ออายุ" (ไปหน้าขายพร้อมเลือกสมาชิกไว้) และปุ่ม "ปล่อยเข้าครั้งนี้" (ต้องใส่เหตุผล, บันทึก `override = true`)
5. **ตัดครั้งวันละครั้ง**: แพ็กเกจ `visits` ตัด 1 ครั้งเฉพาะ check-in แรกของวันนั้น (ตามเวลาไทย) ครั้งต่อมาในวันเดียวกันบันทึกแต่ไม่ตัด
6. แพ็กเกจ `pt` ไม่ใช้เข้ายิม

### 6.2 ขาย
1. เลือกสมาชิก (ไม่บังคับ แต่ **บังคับ** ถ้าตะกร้ามีแพ็กเกจ)
2. แพ็กเกจที่ `seats` = 2 ต้องเลือกสมาชิกคนที่สองด้วย
3. ใส่ส่วนลดเป็นจำนวนเงินหรือเปอร์เซ็นต์ (ยอดสุทธิต้องไม่ติดลบ)
4. เลือกวิธีชำระ ถ้าเป็น PromptPay ระบบแสดง QR ตามยอด แล้วพนักงานกด "ได้รับเงินแล้ว"
5. เรียกฟังก์ชัน `create_sale` ใน transaction เดียว ซึ่งจะ:
   - ออกเลขใบเสร็จ รูปแบบ `R{ปี ค.ศ.}-{ลำดับ 6 หลัก}` เช่น `R2026-000123` รันต่อเนื่องและไม่ซ้ำ
   - บันทึก sales และ sale_items
   - ตัดสต็อกสินค้าที่ `track_stock` และบันทึก stock_movements ถ้าสต็อกไม่พอ บิลทั้งใบจะไม่ถูกบันทึก
   - สร้าง memberships ตามจำนวน `seats` (แพ็กเกจคู่สร้าง 2 แถว ให้สมาชิกแต่ละคน) โดยวันเริ่มเป็นดังนี้
     - `duration`: ถ้าสมาชิกยังมีแพ็กเกจ `duration` ใช้อยู่ จะเริ่มต่อจากวันหมดอายุเดิม (ต่ออายุไม่เสียวัน) ไม่งั้นเริ่มวันนี้
     - `visits`, `pt`: เริ่มวันนี้เสมอ (ถ้าซ้อนกัน ระบบใช้อันที่ใกล้หมดก่อนตามข้อ 6.1)
     - `day`: ใช้ได้เฉพาะวันที่ซื้อ
6. ส่ง `client_request_id` ไปด้วยทุกครั้ง ถ้ากดซ้ำจะได้บิลเดิมกลับมา ไม่เกิดบิลใหม่
7. ใบเสร็จ: แสดงบนจอ, พิมพ์ผ่านเบราว์เซอร์ (รูปแบบกระดาษความร้อน 80 มม.) หรือแชร์ลิงก์ `/r/{receipt_token}` ทาง LINE
   - หน้าลิงก์ใบเสร็จเปิดได้โดยไม่ต้องล็อกอิน แต่แสดงเฉพาะข้อมูลในบิลและชื่อสมาชิก ไม่แสดงเบอร์โทรหรือข้อมูลอื่น

### 6.3 ยกเลิกบิล (เจ้าของเท่านั้น)
ฟังก์ชัน `void_sale` ใน transaction เดียว ต้องใส่เหตุผล และจะ:
- เปลี่ยนสถานะบิลเป็น `voided` (ไม่ลบ)
- คืนสต็อกและบันทึก stock_movements เหตุผล `void`
- เปลี่ยน memberships ที่มาจากบิลนั้นเป็น `cancelled`
- ประวัติ check-in ที่เกิดไปแล้วยังเก็บไว้

### 6.4 พักสมาชิก (freeze)
- พักได้เฉพาะแพ็กเกจ `duration`, `visits` และ `pt` ที่ยังใช้งานอยู่ (ไม่รวม `day`)
- ระหว่างพัก ใช้แพ็กเกจนั้นไม่ได้: เช็กอินไม่ได้ (`duration`, `visits`) และนัดหรือตัดชั่วโมง PT ไม่ได้ (`pt`)
- เมื่อบันทึกการพัก `end_date` จะเลื่อนออกไปเท่ากับจำนวนวันที่พัก
- ยกเลิกการพักก่อนกำหนดได้ โดยวันที่ยังไม่ได้พักจะถูกหักคืนจาก `end_date`

### 6.5 คลาส
- จองได้เมื่อสมาชิกมีแพ็กเกจเข้ายิมที่ใช้ได้ในวันของคลาส (ใช้กติกาเดียวกับข้อ 6.1 ข้อ 2)
- จำนวนการจองที่ไม่ใช่ `cancelled` ต้องไม่เกิน `capacity` ฟังก์ชันจองจะล็อกรอบคลาสก่อนตรวจที่นั่ง เพื่อกันจองพร้อมกันจนเกิน
- เช็กชื่อ "มาแล้ว": ถ้าสมาชิกยังไม่ได้ check-in วันนั้น ระบบจะ check-in ให้ตามกติกาข้อ 6.1 (แพ็กเกจ `visits` ถูกตัด 1 ครั้ง ถ้ายังไม่ถูกตัดในวันนั้น)
- รอบคลาสที่ยกเลิกแล้ว ไม่ให้จองเพิ่ม และแสดงในรายชื่อจองว่ายกเลิก

### 6.6 PT
- นัด PT ต้องอ้างแพ็กเกจ `pt` ที่ใช้งานอยู่และ `pt_left` > 0
- กด "เทรนแล้ว" เพื่อตัด `pt_left` 1 ครั้ง ทำได้ครั้งเดียวต่อนัด
- ยกเลิกนัดไม่ตัดชั่วโมง

### 6.7 สต็อก
- ขาย: ลดอัตโนมัติ (ข้อ 6.2)
- รับเข้า: เพิ่มจำนวน พร้อมหมายเหตุ
- ปรับยอด (เจ้าของ): ตั้งจำนวนตามที่นับได้จริง ระบบบันทึกส่วนต่าง
- เตือนของใกล้หมดเมื่อ `stock_qty` ≤ `low_stock_at`
- สินค้า `track_stock = false` (เช่น ค่าเช่าล็อกเกอร์) ไม่นับสต็อก

## 7. รายงาน

| รายงาน | เนื้อหา |
|---|---|
| ยอดขาย | รายวัน/รายเดือน แยกตามประเภท (แพ็กเกจ/สินค้า) และวิธีชำระ ไม่นับบิลที่ยกเลิก |
| รายการบิล | ค้นตามวันที่ ดูบิลที่ยกเลิกพร้อมเหตุผล |
| การเข้าใช้ | จำนวน check-in ต่อวัน และช่วงเวลาที่คนเข้าเยอะ |
| สมาชิก | ยังใช้งานอยู่ / ใกล้หมดใน 7 วัน (พร้อมเบอร์โทรไว้ติดต่อ) / หมดอายุใน 30 วันที่ผ่านมา |
| สินค้า | ขายดี, ของใกล้หมด |
| การปล่อยเข้า | รายการ check-in แบบ override พร้อมเหตุผลและพนักงาน |
| คลาสและ PT | จำนวนคนเข้าคลาสต่อรอบ, ชั่วโมง PT ที่เทรนแล้วแยกตามเทรนเนอร์ |

พนักงานเห็นเฉพาะยอดขายของวันนี้

## 8. การจัดการข้อผิดพลาด

- **ทำครบหรือไม่ทำเลย**: ขาย, ยกเลิกบิล, เช็กอิน และเช็กชื่อคลาสทำใน transaction เดียว
- **กันบิลซ้ำ**: ใช้ `client_request_id` ที่ unique
- **สต็อกไม่ติดลบ**: มี constraint ที่ฐานข้อมูล
- **เน็ตหลุด**: แสดงแถบ "ออฟไลน์ — ยังไม่ได้บันทึก" ปุ่มบันทึกถูกปิด และเมื่อบันทึกไม่สำเร็จต้องบอกชัดเจน ไม่แสดงว่าสำเร็จ
- **สิทธิ์**: บังคับด้วย Row Level Security และตรวจสิทธิ์ซ้ำในฟังก์ชันที่เจ้าของเท่านั้นใช้ได้
- **ไม่ลบประวัติทางการเงิน**: บิล, check-in และ stock_movements ไม่มีการลบ สมาชิกที่มีประวัติแล้วปิดการใช้งานได้แต่ลบไม่ได้
- **ข้อความผิดพลาดเป็นภาษาไทย** และบอกว่าพนักงานต้องทำอะไรต่อ

## 9. การทดสอบ

- **ฟังก์ชันฐานข้อมูล** (ทดสอบอัตโนมัติ):
  - ตัดครั้งวันละครั้ง
  - เลือกแพ็กเกจที่ใกล้หมดก่อน
  - ต่ออายุแพ็กเกจ `duration` แล้วเริ่มต่อจากวันหมดเดิม ส่วน `visits` เริ่มวันนี้
  - พักสมาชิกแล้ววันหมดอายุเลื่อน และยกเลิกการพักแล้วหักคืน
  - คลาสเต็มแล้วจองไม่ได้ (รวมกรณีจองพร้อมกัน)
  - สต็อกไม่พอแล้วบิลไม่ถูกบันทึก
  - กดซ้ำแล้วได้บิลเดิม
  - ยกเลิกบิลแล้วคืนสต็อกและยกเลิกแพ็กเกจ
  - พนักงานเรียกฟังก์ชันของเจ้าของไม่ได้
- **Logic หน้าจอ** (Vitest): คำนวณยอดและส่วนลด, สร้าง payload PromptPay, จัดสถานะ 🟢/🟡/🔴
- **ทดสอบผ่านเบราว์เซอร์** (Playwright) ด้วยข้อมูลตัวอย่าง: เช็กอิน → ขาย → จองคลาส → ดูรายงาน
- **ทดสอบบนแท็บเล็ตจริง**: ติดตั้ง PWA, สแกน QR ด้วยกล้อง, พิมพ์ใบเสร็จ

## 10. ลำดับการสร้าง

แต่ละขั้นต้องใช้งานได้จริงก่อนไปขั้นต่อไป

1. ตั้งโปรเจกต์ + Supabase + ล็อกอิน + สิทธิ์ + สมาชิก + แบบแพ็กเกจ
2. ขาย + ใบเสร็จ + ยกเลิกบิล
3. เช็กอินด้วย QR + บัตร QR สมาชิก + พักสมาชิก
4. สินค้าและสต็อก
5. คลาสและ PT
6. รายงาน
7. PWA + deploy ขึ้น Vercel + ทดสอบบนแท็บเล็ต
